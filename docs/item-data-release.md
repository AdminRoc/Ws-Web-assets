# Item Data Release Contract

`Ws-Web/data/**` contains two different classes of files:

- Manually maintained leaderboard source records. These files are not item-pipeline inputs and must never be rewritten, reformatted, deleted, or regenerated by item-data workflows.
- Item artifacts under `Ws-Web/data/item/**`. These are the only `Ws-Web` files this release contract may read and mirror.

The contract is declared in `item-artifact-contract.json`. The synchronizer reads only declared source paths from `Ws-Web` and writes only this repository's mirrors/release metadata. The validator compares the private `Ws-Web` item artifacts with the public `Ws-Web-assets` mirror and reports missing files, JSON errors, hash mismatches, duplicate keys, and values that exceed the documented 1 MB EdgeOne KV limit.

Release hashes and byte counts are calculated from canonical LF bytes, matching the committed/public files on GitHub. The synchronizer treats CRLF and LF checkouts as the same artifact, avoiding Windows-only dry-run diffs and mismatched release metadata.

The produced `data/item/wm-items.json` includes Warframe.market's unique `id`. That `id` is the cross-run identity; `slug` is a mutable URL label and may change. A one-time migration from pre-ID artifacts accepts only a unique exact English-name match. Normal item order requests should use `/v2/orders/itemId/{id}`; keep `slug` for display and outbound market links.

The scheduled/manual production workflow first updates the two producer-owned item files in `Ws-Web`, then `sync-item-kv.yml` mirrors every contract-declared item artifact and writes `data/item/item-release.json` here. It publishes only `kv-and-assets` entries to `ITEM_KV`, verifies each readback, and writes `item_release_meta` last. It never writes, reformats, deletes, or otherwise changes `Ws-Web/data/**`.

Current publication target:

```text
EdgeOne project: wfspeed-item
KV binding: ITEM_KV
KV namespace: item_data
Read endpoint: https://item.wfspeed.run/api/kv?key=<key>
Write endpoint: https://item.wfspeed.run/api/update-kv
```

All item artifacts are plaintext JSON. The documented EdgeOne per-value limit is 1 MB. `drops-index.json` is therefore declared `assets-only`; `Ws-Web-item` validates `item_release_meta` against the matching `item-release.json`, pins its public Assets fallback to `assets_revision`, and loads the drop index outside KV.

The main-site static copies at `https://wfspeed.run/data/item/` are a separate EdgeOne Makers publication path. The tracked `Ws-Web/edgeone.json` sets a 30-minute cache for these files. The Assets producer does not call Tencent CDN purge for this Makers domain; `Ws-Web/.github/workflows/verify-public-item-release.yml` waits out that cache window and verifies exact public bytes against the committed Ws-Web artifacts. This workflow verifies publication; it does not deploy through a provider API.

No automated workflow may delete item artifacts or leaderboard source records during the release migration. Old KV keys will be retired manually only after the new release reader has been deployed and verified.
