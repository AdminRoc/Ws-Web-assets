# Item Data Release Contract

`Ws-Web/data/**` contains two different classes of files:

- Manually maintained leaderboard source records. These files are not item-pipeline inputs and must never be rewritten, reformatted, deleted, or regenerated by item-data workflows.
- Item artifacts under `Ws-Web/data/item/**`. These are the only `Ws-Web` files this release contract may read and mirror.

The contract is declared in `item-artifact-contract.json`. It is intentionally read-only during this preparation phase. The validator compares the private `Ws-Web` item artifacts with the public `Ws-Web-assets` mirror and reports missing files, JSON errors, hash mismatches, duplicate keys, and values that exceed the documented 1 MB EdgeOne KV limit.

Run locally from `Ws-Web-assets`:

```powershell
python tools/validate_item_artifacts.py --source-root "C:\Users\Colin Roc\Documents\GitHub\Ws-Web" --report item-artifact-report.json
```

To refresh the public assets mirror from the current `Ws-Web` item artifacts without changing any file in `Ws-Web`:

```powershell
python tools/sync_item_artifacts.py --source-root "C:\Users\Colin Roc\Documents\GitHub\Ws-Web" --dry-run
python tools/sync_item_artifacts.py --source-root "C:\Users\Colin Roc\Documents\GitHub\Ws-Web"
python tools/validate_item_artifacts.py --source-root "C:\Users\Colin Roc\Documents\GitHub\Ws-Web"
```

The synchronizer copies only paths declared by the contract and writes `data/item/item-release.json` in this repository. It never writes, reformats, deletes, or otherwise changes `Ws-Web/data/**`.

Current publication target:

```text
EdgeOne project: wfspeed-item
KV binding: ITEM_KV
KV namespace: item_data
Read endpoint: https://item.wfspeed.run/api/kv?key=<key>
Write endpoint: https://item.wfspeed.run/api/update-kv
```

All item artifacts are plaintext JSON. The documented EdgeOne per-value limit is 1 MB. `drops-index.json` is therefore declared `assets-only`; a later migration will make the item frontend load it from a complete versioned assets release in the background, preserving its existing non-blocking behavior.

No automated workflow may delete item artifacts or leaderboard source records during the release migration. Old KV keys will be retired manually only after the new release reader has been deployed and verified.
